﻿TCG Companion App Design Document



Product Overview
TCG Companion is a companion app for physical trading card games that combines a rules assistant with a turn-and-score engine for live tabletop play. Similar products in the market focus on card tracking, collection management, life counting, or tournament coordination, while this concept combines conversational rules to help with shared-screen scorekeeping for custom card effects.


The app is designed for mobile and tablet use, with support for casting to a smart TV or large monitor so all players can see turn order, active effects, scores, and the current player. Existing companion and life-counter apps show that shared gameplay utilities and multiplayer tracking are already familiar patterns for TCG players.


Product Goals
- Help players resolve rule questions quickly through a TCG chat assistant.
- Track player order, turns, card effects, and score changes during a live match.
- Support local social play on a phone, tablet, or cast display for table visibility
- Make custom or game-specific card logic configurable, including cards such as poison, antidote, and attack cards inspired by tabletop score-based games.
Core Modules


1. TCG GPT / TCG Chatbot
This module acts as a rules assistant. Players can ask questions in natural language such as “Can I play antidote after poison?”, “How does attack damage stack?”, or “What happens if two effects trigger together?” The system should return concise rule answers, show confidence level, and optionally cite the source rulebook or game configuration used by the app.[3][6]


Primary capabilities
- Natural-language question answering for supported TCGs.
- Rule lookup by keyword, card name, phase, or effect type.
- Clarification mode for beginners, compact mode for experienced players.
- Game-specific knowledge packs so each TCG can have different rules.
- Optional admin tool to upload or edit a rule set.


**Important constraint**
The chatbot should not invent rules. For official games, it should use approved rule sources. For custom games, it should only answer from the uploaded design rules for that game.








2. Score Calculator / Turn Engine
This module manages players, turn flow, played card types, and score updates. The user sets player names, chooses the TCG template or custom ruleset, selects the starting player, and the app advances turns clockwise after each action.


The user specifically described card examples like poison, antidote, and attack cards. A score engine for these effects should be rule-driven rather than hardcoded so the same app can support multiple TCGs and custom house rules. Score-based card games such as *Antidote* demonstrate that card outcomes can produce positive or negative points based on the final revealed card state, which supports the need for configurable effect logic.


User Roles
- Host player: Creates the session, enters players, selects the game mode, and controls setup.
- Players: View the shared board, follow turns, and confirm actions.
- Admin/content manager: Adds supported TCGs, rulebooks, scoring definitions, and card effect templates.


Target Platforms
- iOS and Android phone app.
- Tablet-optimized mode for tabletop use.
- Cast/screen-mirror support to smart TVs and large monitors for group visibility.
- Optional web admin panel for managing rulesets and card logic.


Main User Flow
1. Open app.
2. Choose module: TCG Chatbot or Score Calculator
3. For Score Calculator: select a game template or custom TCG profile.
4. Add player names.
5. Choose starting player.
6. Start match.
7. App shows active player and clockwise turn order.
8. On each move, host records the card type played, target player if needed, and resulting effect.
9. Scoreboard updates instantly.
10. At game-end condition, app announces the winner and shows final ranking.


Functional Requirements


 Chatbot Requirements
- Support free-text questions.
- Support question history in the current match.
- Support game selection before asking questions.
- Display short answer first, expanded explanation second.
- Show “rules not found” state when the answer is uncertain.
- Allow manual correction or bookmark of common rulings.


Score Calculator Requirements
- Add 2 to 8+ players.
- Edit player names during setup.
- Select starting player manually.
- Auto-advance turn clockwise.
- Option to reverse direction if a game rule requires it.
- Record card play by card type, card name, or effect category.
- Apply score effects automatically based on configured logic.
- Support temporary status effects such as poison, shield, stun, antidote, attack boost, or heal.
- Show current score, status effects, turn number, and active player.
- End game manually or by rule trigger.
- Announce winner, ties, and full standings.


Example Rule Engine Model
To support many TCGs, the app should use a configurable effect engine.


Example effect types
| Effect Type | Example | Engine Behavior |
|---|---|---|
| Damage | Attack card | Subtract points or health from target |
| Heal | Antidote card | Restore points, remove poison, or cancel a negative state |
| Status Apply | Poison card | Add poison status and apply recurring damage or penalty |
| Status Remove | Cure card | Remove one or more active statuses |
| Modifier | Buff card | Increase next attack or defense value |
| Turn Control | Skip/Reverse | Skip player or change turn direction |
| End Trigger | Final round card | Trigger endgame or scoring phase |


Example custom logic
- Poison card: Apply “Poisoned” state to target for 3 turns, lose 2 health each turn.
- Antidote card: Remove “Poisoned” state and restore 3 health.
- Attack card: Deal 5 damage to selected target.
- Shield card: Prevent the next 4 damage.


This structure is better than hardcoding a single game because it allows the same system to support both standard TCG helpers and original physical card games.

UX and UI Notes
The live match screen should be readable from a distance because the app may be cast to a TV or large monitor. Life-counter and companion tools already emphasize fast visibility and shared table utility, so this design should use large typography, high contrast, and minimal clutter during gameplay.


Recommended design principles:
- Dark tabletop-friendly theme with a light-mode option.
- Very large active-turn indicator.
- Color-coded status markers.
- One-tap common actions.
- Undo last action to handle input mistakes.
- “TV mode” with oversized text and simplified layout.


 Non-Functional Requirements
- Fast response during live play.
- Offline support for saved rule packs and local score matches.
- Reliable state handling so accidental input does not corrupt scores.
- Scalable rules engine for multiple TCGs.
- Secure admin content editing for official/custom rulesets.
- Responsive layout for phone, tablet, and cast display.

Architecture Recommendation
A practical version 1 architecture would be:
- Frontend: Flutter or React Native for cross-platform mobile deployment.
- State management: Riverpod, Bloc, or Redux-style store for deterministic turn updates.
- Backend: Firebase or Supabase for ruleset sync, match templates, and analytics.
- AI layer: LLM-backed rules assistant with retrieval from uploaded game rules.
- Casting: Native screen-cast support or a dedicated cast-friendly secondary display view.


For your team, a cross-platform stack is likely the best choice because the product needs fast UI iteration, mobile deployment, and shared business logic across both modules.

What is an Action Card?
* An Action Card determines the move the player can make when it’s their turn. An action card must be paired with a Character card to make the move valid.


What is a Character Card?
* A character card determines the specific attack or defense the player may make. A Character will also indicate what the Retreat # & Defense Point (DP) is. They are located on the single attack cards.


How to begin?
* All players will roll two dice to determine who will start first. The player with the highest roll will be the first player and decide whether the rotation of players will be clockwise or counterclockwise
* The first player may be the card shuffler or nominate another player to shuffle the Action Card deck and pass out 10 cards to each player.
* Players will also choose one character to be for that round and have ten Character cards of the same character in their hands.
* Players will neither nor show anyone their Action Cards and Character Cards
* Each player will also begin with one Stability Crystal Card, which they will place in front of them. The goal is to defeat a player and collect their stability Crystal Card. The player who obtains three Stability Crystal Cards wins or ops out of the game and other players continue to battle until they win their three. If there are only two players. Two Stability Crystal Cards will be given to each player.
* The first player will claim the character he or she wishes to be then decide the order of player decisions will be clockwise or counter clockwise. 
* No players can be the same character, so once a character is chosen the other players must choose a different character to be.
* Each player will receive 5 energy token to start with and receive one extra energy token, only if they mention it. If it is not requested and the player turn ends, they are no longer allowed to ask or receive an energy token until their next turn.
* The first  player will pick an Action Card and place it face up in the center of the players. He/She will then choose a character card to go along with the action they choose to make. In order for an action card to be valid, they must repent a character at the same time. Remember once the action is completed, the player must discard the Action Card and Character Card (Only if this applies)
* Once the Action or Character has been played and discarded. The player must grab another Action card from the top of the Action Card deck.. Players must also replace another Character Card if used. Players may choose which Character Card they would like to replace the discarded one.
* Players will always have 10 Action Cards and 10 Character Cards when playing. If the player uses two Action Cards in their turn, they must pick up two more Action Cards at the end of their turn.
* Each player will receive 5 energy tokens. Black = 1 energy token, Red = 2 energy token, Purple = 3 energy token. All players may receive 1 energy token every turn. However, no one will remind the player to get their energy token. Once their turn has passed, they can no longer get it.
* When a player is using an Attack Card, combined with a Character Card. The player must use an energy token.
* Regular attacks require 1 energy token. Super attacks require 2 energy tokens Kontrol requires 3 energy tokens and Blitz requires 5 energy tokens.

General:
注意 : Attention
TCG: Trading Card Game
Stacking: Placing the same card on top of each other or using the same card at the same time during the match.
HP (Health Points): The amount of life or vitality a player or character has. HP is reduced when damage is taken from attacks or effects. When a player’s HP reaches 0, they are defeated unless they have or is given a Revive card.
AP (Attack Power): The amount of damage an attack deals to an opponent when the attack is successful.
DP (Defense Power): A value that represents a player’s or character’s defensive strength, helping reduce or withstand incoming attacks.
RP (Retreat Points): Represents a character’s ability to escape combat or reposition. The higher a character’s RP is the lower number a player has to roll. Example, if a character’s RP is 5, the player will only need to roll a 1. Only dice is used to determine whether the player can retreat or must stay and fight. If a character has a RP of 2, the player must roll 4+ on one dice. Players must have a Retreat Card in order to retreat. 
ET (Energy Token): A resource used to activate attacks and special abilities. Energy Tokens are spent when required by a card’s effect or The spiritual force that fuels a warrior’s techniques. Spend Energy Tokens to unleash powerful attacks and devastating abilities.
Weakness: Attacks matching its weakness gain a bonus effect, such as extra damage, status conditions, or special penalties.

Ability:
Ability: A unique effect granted by a card that can influence gameplay.
Passive Ability: An ability that remains active without requiring activation unless otherwise stated.
Active Ability: An ability that must be activated by meeting its requirements or paying its cost.
Status Effect: A temporary condition, such as Poison, Burn, or Stun, that alters a player's or character's abilities.
Cooldown: The number of turns a player must wait before using the same ability or card again.
Turn: A player's opportunity to perform actions according to the game's turn sequence.
Round: A complete cycle in which every player has taken one turn.
Card Effect: The special rules or abilities printed on a card.
Successful Attack: An attack that meets all requirements to hit and applies its effects.
Miss: An attack that fails to hit its target and does not deal damage unless stated otherwise.
Critical Hit: An attack that deals additional damage or gains an enhanced effect when specific conditions are met.
Combo: A sequence of attacks or abilities that work together to create a stronger effect.
Counter: A defensive response that interrupts, redirects, or retaliates against an opponent's action.
Redirect: Changes the target of an attack or ability to another legal target.
Heal: Restores lost HP. A player's HP cannot exceed its maximum value unless a card effect states otherwise.
Victory: A player has won 3 Stability Crystals and have saved their world from destruction.

OFFICIAL ZOMBIE MODE RULES

When a player has 5 Poison Cards, the dealer gives them a Zombie Mode Card. The card must be placed face-up so all players know that the infected player is now a Zombie.

Zombie Mode Restrictions:
- Players in Zombie Mode cannot use any Character Cards or Character Card abilities.
- A player in Zombie Mode cannot win or claim a Stability Crystal Card (they must be cured back to regular mode before taking a crystal).
- All attacks must come from the Zombie Mode Card: Venom Strike (15 AP, infects target with +1 Poison Card on hit).

Zombie Stats:
- Starting HP: 40 HP (can only increase via Vitality or Heal cards).
- Turn Regeneration: At the beginning of each Zombie player's turn, they automatically recover +10 HP even if they took damage in the previous round.
- Kontrol Immunity: Mindless zombies are immune to Kontrol Cards.

Revival Rules:
If Zombie HP is reduced to 0, they immediately revive:
- 5 Poison Cards: Revives at 10 HP.
- 6-7 Poison Cards: Revives at 20 HP.
- 8+ Poison Cards: Revives at 40 HP.

Weaknesses:
- Fire and Lightning are especially effective against Zombies. Whenever a Zombie is hit by Fire or Lightning attack, the attack deals normal damage AND removes 1 Poison Card. (Only removes poison while in Zombie Mode).

Curing Zombie Mode:
- Playing an Antidote or reducing poison below 5 immediately cures the player. Discard the Zombie Mode Card and return to the exact HP you had before entering Zombie Mode (pre-zombie HP). Remaining poison cards continue to deal -10 HP per round until cured.
